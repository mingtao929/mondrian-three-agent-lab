# 蒙德里安几何狂想 三 Agent 版本

本目录是完整网页的运行源码。A、B、C 通过 MCP 进入同一实验房间；研究者在网页上建房、控制流程、观察和导出。以后维护时以这里的任务规则、角色观察、房间状态和事件记录为准。

## 本地启动

在此目录用 Node.js 24 或以上运行 `npm ci`，然后运行 `npm start`，浏览器打开 http://127.0.0.1:4327/ 。日常验证运行 `npm test`。默认数据库是 `data/three-agents.sqlite`，应保存在使用者本机。

五层由 [server.js](src/server.js) 组装。排查一条动作时，按 **MCP 工具 → 席位权限与观察 → 拼图引擎 → 事件入库 → 网页及导出** 追踪。网页观察是研究者功能，Agent 领取的是模块 02 裁剪后的数据。

现有 Python 仓库里的轮换、凭据隔离和重复提交用例可作为模块 03 的验收参照。正式平台只保留一套房间状态、一套规则和一套事件记录。复用 Python 的测试场景时，应在本平台的 MCP 入口验证同样的行为。三个真实 WorkBuddy 会话是否隔离连接器，仍须用实际工具列表和回执验收。

## 默认 MCP 实验流程

创建房间后为每一席位单独生成连接，并在三个独立会话中调用领取工具。网页显示就绪后，由研究者开始实验。连接器共享范围取决于客户端配置，先检查每个会话实际加载的工具。实验完成后从记录页导出。

## 历史接入流程

以下为旧 API／HTTP 运行模式的记录。它有独立的设置界面和调度规则，属于早期版本。当前 `npm start` 启动 MCP 模式。

1. 创建三Agent实验，在教程中点击“先配置三个Agent”。
2. 分别配置A/B/C，可使用相同或不同服务：OpenAI兼容填写Base URL、实际model ID和Key；HTTP填写已运行适配器的完整POST地址及Token。每位角色分别保存并启动。
3. 下载房间访问凭据，再关闭设置，点击“开始三Agent实验”。三个都启用后才能开始。
4. 每个agent独立完成平移、四步内到达、矩形旋转、两三角形组合四道练习。先完成的等待；三个全部通过后自动进入正式第一关。
5. 用顶部观察视角切换A/B/C，只读查看。研究者不能操作任何碎片、聊天或替agent提交。
6. 三个agent均返回submit，才统一判分。任何正式移动/旋转撤销全部确认，迟到旧画面的submit丢弃。未通过继续协作；第一关通过自动进入第二关，第二关通过结束。
7. 设置中导出JSON/CSV和三视角回放。结束本次实验会终止任务，不是暂停。访问凭据可在首页恢复。

练习和正式两关共用40分钟。正式关卡共享1000能量；练习不扣能量，进入正式任务时清零练习步数。两关仍为18/27碎片、13/18目标区域，累计31区域。

## 接入规则

HTTP协议沿用mgf-agent-v1，但本版新增agent动作submit。练习submit检查该角色当前练习；正式submit只表达该角色准备提交，不会越过三方共识。不得start/next/stop。

observation增加sessionPhase、practiceIndex、practiceProgress、practiceResult、ready、lastResult和boardRevision。phase=waiting表示自己的四道练习已过。模型输入只包含该角色可见几何和公开对话，不含答案、groupType、其他练习几何或访问令牌。外部运行时必须按(sessionId,role)隔离记忆。

每角色3.5秒调度、一个在途请求、60秒超时。动作违规会私下反馈被拒绝动作及原因，连续3次违规暂停；有效动作后清零。超时、连接异常和HTTP 408/409/429/5xx最多重试2次，等待2秒、4秒；401/403/404等配置错误直接暂停。手动保存配置会清零重试状态。不会回退演示。重试可能增加服务商费用。三路调用可能产生服务商费用，本版没有金额预算上限；Key只保留内存，重启需重填并启用。

规则演示根据可见练习目标完成四道练习；正式关卡只提供可见线索并响应公开指引，不会偷读自己的隐藏答案，也不保证自主完成正式任务。真实模型效果仍需实际服务和密钥验证。

## 研究记录和差异

日志记录每次实际发送的角色观测、动作、聊天、配置、耗时及用量；完整历史仅研究者导出，观察链接无配置、操作、导出权限。回放展示最近100条聊天，完整聊天在事件表。状态与日志SQLite持久化，重启后全部agent暂停，不自动恢复付费调用。

本版不是人人或人机条件，三套独立练习是按需求重建的实验规则。结构化输入不等同于人类视觉。复制的旧版PDF/视频仅保留为历史素材，不在本版界面或媒体路由使用，避免将真人操作说明当作本版流程；请以本README和页面使用帮助为准。

代码调研参考：https://github.com/neuhai/human-agent-collab 。没有引入其实现；本版基于当前拼图平台独立扩展。

提示版本 current-state-v2：OpenAI兼容接口的独立练习不携带历史聊天，正式任务保留公开线索；最新角色状态单独置于输入末尾。增加局部顶点旋转和提交失败检查提示。这是提示支持干预，不能将其前后表现直接当作相同实验条件。日志 agent_request 标记 promptVersion。

提示版本 visible-world-vertices-v3：为每个角色的可见碎片及目标附上由可见顶点、位置和角度计算的 worldVertices；不含目标对应关系或隐藏目标。观察页面加入任务目标、完成条件、目标示意与最近动作，移动/旋转采用650ms插值展示，尊重减少动态效果设置。动画不改变判分或模拟状态。


## WorkBuddy 桌面版接入 B（MCP）

桌面版已登录不等于可以独立运行内置 CLI。本机 B 接入改走 `src/workbuddy-mcp.js`：平台向本机 4331/act 请求 B 决策；已登录的 WorkBuddy 通过 stdio MCP 的 `next_puzzle_turn` 领取观察、`submit_puzzle_turn` 回传一次性回合结果。中继绑定一个房间和 B 角色，不提供研究者权限、隐藏目标、其他角色私有状态或任意文件/终端操作。超时、重复及过期提交被拒绝。

配置保存在任务工作目录 `work/workbuddy-mcp-local.json`；它包含本机中继凭据，请勿分享或提交。WorkBuddy 的自定义 MCP 配置增加 `mondrian-agent-b`，其余连接器不变。首次启用可能需要用户在 WorkBuddy 桌面确认连接器授权；不能通过修改审批缓存绕过。只有桌面端实际领取回合并返回动作后，才算真实连通。

联通验证房间的 A/C 使用规则演示、仅 B 使用 WorkBuddy，不应归类为三真实 Agent 实验。旧真实实验记录保留，WorkBuddy 中途替换不应被当作同一实验条件。


## 全局暂停与连接取消（2026-10-23）

实验设置新增“暂停整个实验（冻结计时）”。研究者暂停时冻结剩余时间、停止新回合并取消在途HTTP调用；恢复后从当前关卡和位置领取新回合。暂停和恢复均写入事件日志，不能当作无干预实验。单Agent的“保存并暂停”只控制该Agent，不冻结整场计时。结束可在暂停期间执行，且结束后的新记录计时固定。

API沿用researcher action，新增type=pause/resume；观察者、Agent均无权操作。暂停/恢复使用runEpoch拒绝旧响应；重配会取消该角色旧连接。服务关闭先终止并等待在途任务，再关闭数据库。取消仅保证平台停止等待并拒绝旧动作，上游模型是否停止生成及计费取决于服务商。

新增同源精确检查（包括端口）、页面嵌入限制及CSP。仅用于本机部署；不代表经过公网渗透测试。WorkBuddy桌面对话终止工具循环仍需人工重新发起任务，平台不绕过桌面授权、不用演示程序替换真实Agent。

新增测试覆盖计时暂停/恢复、在途连接取消、新回合恢复、跨房间凭据、跨端口来源以及6个房间并发隔离。并发验证使用模拟Agent，不代表真实云模型的吞吐保证。
